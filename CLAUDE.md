# MyDigitalTwin — Claude Code Guide

## Project overview

Spark + Delta Lake pipeline for personal GDPR data analysis. Ingests raw exports from Instagram, Google, Spotify, TikTok, Twitter, Netflix into a centralized warehouse, then runs ML notebooks (clustering, ALS, CLIP, social graph) and exposes results in a Dash dashboard.

## Config architecture

Three files, three roles — never mix them:

- `config.yaml` — personal non-secret data (close friends, anchor artists, CLIP labels). Never commit. Generated by Copier.
- `.env` — API keys and secrets (Spotify, Gemini, TMDB). Never commit.
- `config.py` — technical paths and runtime settings only. No personal data here.

Always import paths from `config.py`. Never hardcode `/opt/spark/data` or `./data` directly.

## Project structure

```
src/ingestion/         Parsers (inbox → processed)
src/ingestion/parsers/ One parser per platform
src/ingestion/base.py  ParserBase class
src/ingestion/run_all.py  Entry point for ingestion
src/scripts/           Analytical notebooks (01 → 07)
app/                   Dash dashboard
data/inbox/            Drop zone for raw GDPR exports
data/processed/        Parsed exports by source
data/warehouse/        Parquet/Delta analytical tables
template/              Copier .jinja templates
```

## Data flow

```
data/inbox/ → Parsers → data/processed/<SOURCE>/ → Notebooks (Spark) → data/warehouse/ → Dashboard
```

Parsers only move files. Spark sessions live in the notebooks, not in parsers.

## Incremental ingestion

- Inbox → processed: `OVERWRITE=False` for Instagram/Google/Spotify, `OVERWRITE=True` for TikTok/Twitter/Netflix
- Processed → warehouse: always use `MERGE INTO` Delta Lake. Never `.mode("overwrite")` on warehouse tables.

## Adding a new data source

1. Create `src/ingestion/parsers/<platform>.py` extending `ParserBase`
2. Register it in `src/ingestion/run_all.py`
3. Create `src/scripts/01_exploration/<platform>.ipynb`
4. Use explicit Spark schema (no `inferSchema`)
5. Write to warehouse with `MERGE INTO`

## Testing

```bash
pytest -m unit -v                        # unit tests
pytest tests/data_quality/ -v --tb=short # Pandera schema tests
ruff check .                             # lint
```

CI runs all three on every PR via `.github/workflows/ci.yml`.

## Environment detection

`config.py` auto-detects the runtime environment:
- Local: `./data`
- Spark Docker container: `/opt/spark/data`
- Dashboard Docker container: `/app/data`

## Git workflow

`main` is protected. Always work on a feature branch and open a PR. Branch naming: `feat/`, `fix/`, `docs/`, `demo/`.

## Copier

Generates `config.yaml` and `.env` from `template/*.jinja`. Run with:
```bash
pip install copier
copier copy . ../my-digital-twin
```

## Key dependencies

- PySpark 3.5 + Delta Lake 3.x
- Dash / Plotly for the dashboard
- Pandera for data quality schemas
- Ruff for linting
- pytest for unit tests
