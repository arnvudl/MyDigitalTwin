## Summary

Schema files already exist for all 6 platforms (`tests/schemas/`) and the data-quality test suite (`tests/data_quality/test_dq_warehouse.py`) already exercises them under `@pytest.mark.data_quality`. The remaining work is an audit pass: verify every schema covers all columns produced by the matching parser's `transform()` output, add missing value constraints, ensure `strict=False` is set consistently (currently it defaults to `False` but is not explicit), and document the `netflix_views` schema's reliance on a `raw_title` column that doesn't appear in the schema definition.

## Architecture Decisions

- **`strict=False` explicit**: Pandera defaults to `False`, but explicit declaration documents that extra columns are intentional — prevents confusion when new platform columns appear
- **Validate post-load**: Tests read from `data/warehouse/` via `pd.read_parquet()`, not from `data/processed/`. This follows the existing DQ test pattern and avoids duplicating parser logic
- **`raw_title` in netflix.py**: The DQ test uses `raw_title` for the duplicate check but the schema omits it — adding it makes the contract complete
- **Memory Album in scope**: `memory_album.py` schemas cover ML pipeline output, not a GDPR parser — kept in scope since the DQ suite already exercises them
