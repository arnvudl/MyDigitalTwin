## Summary

Add an automated integration test suite for the Dash dashboard (`app/`) using a two-tier approach: Flask test client for page-load validation (all 10 pages) and `dash_duo` for interactive callback testing (3 key callbacks). All warehouse reads are mocked with static fixtures — no Spark session or live data required. Tests run under 120 seconds in CI via `pytest -m integration`.

## Implementation Phases

### Phase 1: Test Infrastructure

**Responsible**: Dashboard Lead  
**Output**: `tests/integration/` scaffold, fixtures, conftest, pytest config  
**Dependencies**: None (independent of all other phases)

**Deliverables**:

1. `tests/integration/__init__.py` — empty, marks as package
2. `tests/integration/conftest.py`:
   - Session-scoped `client` fixture: `app.server.test_client()`
   - Autouse `mock_warehouse` fixture: patches `_read_delta` in all page modules to return static DataFrames
3. `tests/integration/fixtures/` — one file per warehouse table with minimal static DataFrame (3-5 rows covering all columns used by the page)
4. `pytest.ini` — add `integration` to `markers` list
5. `requirements.txt` — add `dash[testing]`

**Gating**: `pytest tests/integration/ --collect-only` lists tests without import errors.

---

### Phase 2: Page-Load Tests

**Responsible**: Dashboard Lead  
**Output**: `tests/integration/test_pages.py`  
**Dependencies**: Phase 1 infrastructure

**Deliverables**:

1. `tests/integration/test_pages.py`:
   - Parametrized test over all 10 page URLs: `/`, `/clusters`, `/spotify`, `/netflix`, `/social`, `/photos`, `/memory-album`, `/psy`, `/timeline`, `/inventory`
   - Assert: HTTP 200, non-empty body
   - Mark: `@pytest.mark.integration`

**Acceptance**: All 10 pages return 200 with mocked data. Suite completes in < 30 seconds.

---

### Phase 3: Callback Interaction Tests

**Responsible**: Dashboard Lead  
**Output**: `tests/integration/test_callbacks.py`  
**Dependencies**: Phase 1 + Phase 2

**Deliverables**:

1. `tests/integration/test_callbacks.py` using `dash_duo`:
   - **Test 1** — Clusters page: select cluster from dropdown → assert graph has ≥ 1 trace
   - **Test 2** — Spotify page: apply time range filter → assert chart updates without error panel
   - **Test 3** — Invalid input fallback: trigger callback with None input → assert empty-state component returned, no exception raised

**Acceptance**: 3 callback tests pass with `dash_duo`. Suite completes in < 90 seconds (including browser startup).

## CI/CD Integration

Add to `.github/workflows/ci.yml`:

```yaml
- name: Integration tests
  run: pytest -m integration -v --tb=short
```

ChromeDriver must be available in the CI runner image. For GitHub Actions, use `actions/setup-chrome` or the pre-installed Chrome on `ubuntu-latest`.

---

## Implementation Order

1. Phase 1 (infrastructure) — unblocks everything
2. Phase 2 (page-load tests) — fast wins, validates mocking strategy
3. Phase 3 (callback tests) — requires browser, run last

---

## Architecture Decisions

- **Flask client vs. dash_duo**: Flask client for render checks (no browser), dash_duo only for callbacks requiring JS execution
- **Autouse mock**: Patching `_read_delta` centrally in conftest avoids per-test boilerplate and ensures no test ever touches real warehouse data
- **Session-scoped app**: App instantiation runs once; individual tests are stateless
