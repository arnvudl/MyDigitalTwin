# Implementation Plan: Convert Analytical Notebooks to Production Python Scripts

**Branch**: `011-convert-notebooks-python` | **Date**: 2026-05-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/011-convert-notebooks-python/spec.md`

---

## Summary

Convert 15 Jupyter notebooks in `src/scripts/` to standalone production `.py` scripts. Each script manages its own Spark session lifecycle (create → process → stop), removes all visualizations and exploration cells, and writes to Delta Lake using the existing MERGE patterns. A `run_pipeline.py` entry point orchestrates all 19 stages (15 converted + 4 existing `.py` scripts) with individual or full-pipeline execution. A `validate_outputs.py` smoke-test script verifies output table schemas and row counts post-conversion.

---

## Technical Context (MyDigitalTwin-Specific)

**Language/Version**: Python 3.11

**Primary Dependencies**: PySpark 3.5.5, Delta Lake 3.2.0, `build_spark_session()` from `config.py`

**Storage**: Delta Lake file-based warehouse; all writes via MERGE INTO (incremental) or delete+append (computed tables with vectors)

**Testing**: `validate_outputs.py` smoke test (schema + row count); `ruff check .` linting

**Target Platform**: Docker Spark container (`/opt/spark/data`); local Python 3.11 (`./data`)

**Performance Goals**: Chaque script reproduit exactement la config Spark du notebook source. `google_youtube` = `6g`, `03_memory_album/01_visual_embeddings` = `4g` + snappy, tous les autres = défaut `4g`. `06_social/01_social_graph` = **pas de Spark** (pure Python).

**Constraints**:
- All paths from `config.py` — no hardcoded paths
- `spark.stop()` in `try/finally` in every script
- No `.cache()` unless strictly necessary; no `.collect()` on large datasets
- No visualizations (matplotlib, plotly inline)
- Existing `.py` scripts (04_clone, 07_psy, 05_CLIP/00, 03_memory_album/scripts/) must not be modified

### Phase G: Orchestration + Validation ✓ COMPLETE

**Deliverables**:

1. **`run_pipeline.py`** (project root):
   - Stage list: 19 stages in order (see data-model.md)
   - `python run_pipeline.py` → runs all stages sequentially
   - `python run_pipeline.py --stage instagram` → runs stage matching name
   - `python run_pipeline.py --from 7 --to 9` → runs stages 7–9 (clusters)
   - Each stage runs as `subprocess.run([sys.executable, script_path], check=True)`
   - On failure: prints failing stage + error, stops pipeline

2. **`validate_outputs.py`** (project root):
   - Spark session: `driver_memory="1g"`, `shuffle_partitions=2` (read-only validation)
   - For each expected table: check Delta table exists, read schema, count rows
   - Report: `✓ table_name — schema OK, N rows` or `✗ table_name — MISSING / schema mismatch / 0 rows`
   - Exit code 0 if all pass, 1 if any fail

**Gate**: `python run_pipeline.py` completes end-to-end; `python validate_outputs.py` exits 0; `ruff check .` passes.

## Architecture Decision Summary

- **`subprocess.run()` for orchestration**: Preserves independent Spark session lifecycle per script; prevents cross-script memory leakage
- **Paramètres Spark copiés fidèlement depuis chaque notebook**: `google_youtube` = 6g, `visual_embeddings` = 4g+snappy, tous les autres = défaut 4g. Aucune normalisation imposée.
- **`try/finally spark.stop()`**: Garantit la libération de la session même en cas d'erreur
- **`06_social` sans Spark**: Le notebook le confirme explicitement — pure Python JSON séquentiel
- **`.cache()` conservé dans `05_CLIP/02`**: Usage légitime dans le notebook source, conservé tel quel
- **Suppression des cellules exploration**: Les scripts de production ne génèrent pas de bruit console ; le dashboard gère l'affichage
- **`validate_outputs.py` comme smoke test**: Léger, tourne post-conversion pour détecter toute perte de données ou dérive de schéma
